# 矿井巷道三维图档渲染与档案加工平台

React 18 + TypeScript + 原生 WebGPU/WGSL 实现的矿井巷道三维渲染与图档档案管理平台。
以模拟测量数据生成 **总长约 12 万米** 的两期巷道模型，覆盖从测量建档、体块加工、
五图层渲染、两期对比到归档检索的完整链路。

## 运行

```bash
npm install
npm run dev        # http://127.0.0.1:5173
npm run build      # 类型检查 + 生产构建
npm run test:unit  # 34 项 Node 单元/逻辑冒烟测试
npm run test:e2e   # 24 项真实 Chrome + WebGPU 端到端测试（需先 npm run dev）
```

> 需 Chrome / Edge 113+ 且开启硬件加速（`chrome://gpu` 确认 WebGPU 可用）。
> 无 WebGPU 时视口显示降级提示，应用其余部分仍可操作。

## 需求与实现对照

| 需求 | 实现 |
| --- | --- |
| 中心线 + 断面参数生成体块 | `core/mesh.ts` 沿中心线逐点建立 T/S/U 标架，按直墙半圆拱/矩形/圆形断面环扫掠成封闭网格（含两端封口） |
| 五图层渲染 | 巷道体块、支护、管线、风门、机电设备各为独立 `RenderMesh`，`LayerPanel` 独立开关与单层独显 |
| 视口裁剪只画视野内段 | 每条巷道一个 AABB 裁剪分段；CPU 用 viewProj 提取 6 个视锥面做正顶点测试，可见段索引压缩进动态索引缓冲，不可见段零绘制 |
| 远景支护/螺栓降级简模 | 支护生成 nearOnly 高模（完整钢拱架线环 + 径向锚杆/螺栓）与 farOnly 简模（每 5 架 1 根标记线）两套网格，视距 420 m 自动切换，拉近补回 |
| 12 万米拖动缩放跟手 | 轨道相机指数缩放 + 直接事件驱动；每网格仅一次 `writeBuffer` 压缩可见索引，双缓冲动态索引区避免 GPU 占用冲突；HUD 实时显示帧耗时/绘制调用 |
| 点中巷道弹属性卡并高亮整条 | CPU 射线拾取：整体 AABB 粗判 → 体块分段 AABB 精判；高亮写入每巷道 style 存储缓冲，WGSL 中整巷橙色呼吸脉冲 |
| 图层开关 / 单层独显 | 勾选框控制 `layerEnabled`，「独」按钮进入 solo 模式只渲染该层 |
| 剖切面沿走向切内部 | 全局轴对齐剖切面（X/Y/Z 可选，滑块沿包围盒推进），WGSL fragment 中 `dot(n,p)+d` 判定 discard，实体与线框统一生效 |
| 两期左右分屏对比 | 两个独立 `Viewport3D` 共享相机状态（双向联动、回环抑制）；一期红标废弃段、二期绿标新增/改造段 |
| 原始测量建档编号 | `ArchiveStore.registerMeasurement` 生成 `CL-YYYY-####` 档案号，记录巷数/测点数/长度/期次 |
| 加工图档版本比对 | 加工生成 `GT-####` 版本，每巷道几何/属性双指纹；`diffVersions` 输出新增/废弃/几何变更/属性变更四类差异报告与长度净变化 |
| 归档后三维检索 | 版本可归档；按巷道名关键字 + 标高区间 + 采区组合检索，命中列表点击即镜头定位 |

## 架构

```
src/
├─ core/
│  ├─ types.ts        数据模型（巷道/断面/设施/档案/版本/差异报告）
│  ├─ math.ts         mat4、轨道相机、视锥/射线、AABB 相交
│  ├─ mockData.ts     确定性 PRNG 两期测量数据（12 万米、新增/废弃/改造）
│  ├─ mesh.ts         扫掠体块、支护双 LOD、管线/风门/设备网格 + 裁剪分段表
│  └─ archive.ts      建档/版本/指纹/差异/检索，localStorage 持久化
├─ renderer/
│  ├─ shaders.ts      WGSL：实体光照管线 + 线框管线（剖切/雾/高亮）
│  ├─ WebGPURenderer.ts  设备/管线/缓冲、视锥裁剪、动态索引压缩、LOD、拾取
│  └─ OrbitController.ts 轨道相机（旋转/平移/指数缩放/点击与拖动区分）
├─ components/        Viewport3D、LayerPanel、ClipPanel、PropertyCard、ArchivePanel
└─ App.tsx            单视口/分屏模式与全局状态编排
```

### 渲染管线要点

- **单套顶点布局**：position / normal / color / roadwayId 四个缓冲，实体与线框两条 pipeline 复用。
- **每巷道 style 存储缓冲**：16 字节/巷，0=顶点色、1=高亮脉冲、2=差异着色，切换无需重建网格。
- **视锥裁剪**：分段 AABB 对 6 个视锥面做正顶点测试；相邻可见段合并区间后一次性拷贝，
  绘制调用数只与可见区间数相关，与总段数解耦。
- **LOD**：以相机轨道半径为距离度量，支护层高/简模二选一提交，索引规模相差约 70 倍。
- **深度精度**：远裁剪面收紧到 6 万米，拾取反投影与该值保持一致以减少求逆误差。

## 数据规模（默认模拟）

- 一期约 60+ 条命名巷道、12.1 万米、4000+ 测量控制点
- 二期在一期基础上：~12% 废弃、~18% 几何改造（下沉+延伸）、新增 7 条巷道
- 单期渲染网格约 230 万顶点 / 370 万索引，视锥裁剪后典型仅绘制 40 万索引量级
